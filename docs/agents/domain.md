# Domain Docs

## Layout and reading rules

This repository uses a single-context layout.

Before exploring the codebase:
- Read root `GLOSSARY.md` if present.
- Read relevant decisions in `docs/adr/` if present.
- Consult subsystem designs in `docs/HLSD/` when relevant.

Proceed silently when glossary or ADR files are absent.
Create them through domain-modeling when terminology or decisions
are resolved, following the repository's documentation rules.

## Vocabulary

Use glossary terms consistently in issue titles, proposals,
hypotheses, and test names.

For an undefined concept, check existing project terminology.
Record a genuine vocabulary gap for domain-modeling.

## Decision conflicts

Explicitly identify any proposal that contradicts an existing ADR,
including the decision and the reason to reconsider it.
